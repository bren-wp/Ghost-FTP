# Ghost FTP v0.95.37 — Local SQLite, credentials, edit watcher, keep-up-to-date audit

**Storage:** `ghostftp.db` already uses bundled SQLite. SQLite provides transactional structure and indexed data; it **does not encrypt data by default**. Ghost FTP keeps the passwords and key passphrases in Windows-native credentials (using Windows platform protection) or Linux native secret service. A portable Argon2id-encrypted backup is separate from the active OS keyring. SQLite includes sync_state, transfer_ledger, settings, snippets, search/index cache and a keychain metadata manifest. Connections remain in compatibility-preserved sanitized `profiles.json`. The 0.95.36 profile-store write layer refuses non-empty password/passphrase fields.

**Reliability changes in 0.95.37:** open the database with foreign keys actually verified on, configure a five-second lock wait, and report a journal-mode fallback. On code files at most 8 MiB, edited copies are SHA-256 fingerprinted to avoid missing rapid equal-size edits when the OS reports the same timestamp. Special files or symbolic links remain forbidden as an automatic upload source; unsuccessful transfers are not acknowledged. Generated .NET FileSystemWatcher keep-up-to-date scripts consume only events matching their own prefix, retaining a 60-second fallback reconcile.

**Current watch model:** the in-app recursive watcher synchronizes when Ghost FTP is open. It is event-driven with debouncing and a polling fallback, not a real-time deterministic operating system service. Network latency, remote server limits and scheduled retries still apply. Use additive local-to-remote for live website edits; Mirror deletion is subject to explicit safety limits.

**Remaining gaps:** Built-in editor PHP/JS/HTML/CSS syntax highlighting, matching brackets, intelligent completion and Ctrl+F do not yet ship as an integrated native pane. External editors provide those capabilities. App credential recovery under locked/missing Windows or Linux secret stores needs physical machine tests, and cloud providers must be benchmarked with real authenticated endpoints. Remote transfers are not guaranteed globally atomic across FTP/SFTP/cloud adapters; avoid unqualified feature-parity or high-volume throughput claims.
