# Ghost FTP v0.95.53 — Full source security audit

**Scope and evidence.** This is a *repository-wide source, workflow, dependency-contract and release-integrity review*, not a completed independent penetration test. The mandatory `tools/audits/full-security-code-audit.mjs` scans production Rust, TypeScript/React, Android Kotlin, macOS Swift and Go plus operational code. Its JSON artifact is source-specific and its negative tests inject TLS and SSH bypasses. CI also performs `npm audit --omit=dev --audit-level=high`, guarded Rust compilation/tests/Clippy, Android lint/build/emulator tests, macOS SwiftPM tests, real Windows/Linux installed-app smoke, protocol E2E and Windows process hardening. GitHub private Dependabot/code-scanning/secret-scanning alert records are not available in the connected read-only GitHub interface and are **not claimed checked**.

## Findings, priority, remediation

| Severity | Surface | Evidence and state | Decision |
| --- | --- | --- | --- |
| P0 release metadata | Original `v0.95.51` | Six CI runs and recovery restored 21 source-pinned assets; GitHub later reported `prerelease=false` despite unsigned Android / ad-hoc macOS Preview | Reverify original SHA/tag, asset count and checksums, correct classification before owner-authorized cleanup; retain public asset bytes immutable |
| P0 data integrity | macOS FTP upload `STOR` | FTP STOR normally overwrites an existing remote path. Prior UI did not require replacement confirmation. Source-level evidence | v0.95.53 adds complete remote listing preflight and case/Unicode alias collision guard, refusing STOR if a matching name exists; race-free remote atomic creation **still unavailable** without server support |
| P1 filesystem race | macOS upload source | Unsafe symlink/changed-file source could be mistaken for valid upload | v0.95.52 opened with `O_NOFOLLOW`, checks descriptor/inode, size, ctime/mtime, bytes before and after completion; v0.95.53 prevents navigation/login from interleaving active transfer |
| P1 trust store | Desktop SSH `known_hosts` | Replacement path aliases would be sensitive | v0.95.51 rejects symlinks/Unix hardlinks and validates stale file identity; regression tests protect preserved records |
| P1 unimplemented protocols | macOS explicit FTPS / SFTP | The actual `FTPControlSession.connect` refuses every protocol except FTP. TCP reachability is **not** secure authentication | **OPEN:** must implement certificate/hostname-verified TLS control+data for FTPS, SSH host-key pinning/TOFU confirmation, auth, file ops, errors, cancellation and real E2E. UI must not claim support while blocked |
| P1 credentials and transport | Plain FTP | USER/PASS and file payloads travel without encryption; application warns | Do not silently upgrade or claim encryption. Recommend secure protocols on supported clients and block untrusted-network FTP by product policy in future |
| P1 distributions | Signing and updates | Android production APK/AAB are unsigned; macOS ZIP ad-hoc; Windows Authenticode and real hardware upgrades lack mandatory proof | Enforce `preview` release channel; block stable. Test app identity-preserving upgrades on real devices before Play or notarized distribution |
| P2 large-volume durability | FTP/SFTP/local sync/backups | Static tests are not power-loss/fault-injection or >4 GiB remote digest validation | **OPEN:** verify SHA-256 end to end, interrupted upload rollback, resume, crash recovery, disk-full, Unicode, symlink swaps, and both ends of filesystem sync |
| P2 data at rest | SQLite, profiles, Keychain, Keystore, Secret Service | SQLite is transactional but *not encrypted*; credentials use OS services where supported | Preserve migration compatibility and protected secret stores; device-level Keychain/Keystore and Linux Secret Service API-failure QA remain open |
| P2 availability and power | Remote inventory, connection retries | Bounded directory listing and control buffers protect some untrusted server inputs | **OPEN:** memory/Battery profiling with long-running network fault injection and platform hardware; CI cannot prove low power use |
| P2 UI and access | 75 reference screens | Static UI contracts cannot verify 1:1 running pixels or accessible focus/VoiceOver across every screen | **OPEN:** attach real per-platform screenshot and interactive accessibility acceptance matrix |

## Negative regression policy
- No `danger_accept_invalid_certs(true)`, Go `InsecureSkipVerify: true`, `StrictHostKeyChecking=no`, `curl -k/--insecure` or direct plaintext password console logging in known production source scopes. The audit emits path/line only, not secrets.
- Verify physical host-key mismatch, unexpected FTP replies, short downloads, cancellation, local symlink/hardlink aliases, failed UI actions, disconnection, and unavailable remote inventory. The macOS FTP duplicate-file block uses a preflight and **does not** assert atomic server-side no-overwrite.
- Unknown source paths, reflection, native resources, supply-chain advisories, cloud account systems, updater recovery and migration retention need expert manual inspection and independent dynamic testing.

## Exit criteria
All exact-head CI gates green; no silent release classification downgrade; source and destination content hashes compared on representative large live transfers; secure macOS FTPS/SFTP E2E; production signer identity tests; offline/online install/uninstall/upgrade smoke on real target hardware; no severe open dependency/secret scanning alerts; reviewed user data preservation and accessibility.
