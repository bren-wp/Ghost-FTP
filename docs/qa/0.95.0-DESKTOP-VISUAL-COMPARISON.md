# Ghost FTP 0.95.0 — Windows/Linux native visual comparison

**Evidence status: partial.** Actual images were captured from running applications and compared to the **user-supplied** `GhostFTP-Premium-Brand-UI(4).zip` concept art. Never present the reference as a real application screenshot or treat file-row/progress differences as pixel regressions when the real app has no configured connection.

## Evidence provenance

- Approved source concept: `screens/windows/`, **30** designs, each **1290 × 852** pixels; `screens/linux/`, **29** designs, likewise **1290 × 852**. These are design references; illustrations show synthetic file names, connections and transfer history.
- Real Windows **0.94.0** baseline: native QA run [38089027162](https://github.com/bren-wp/Ghost-FTP/actions/runs/38089027162), Windows Preview QA artifact **11683762992**.
- Real Windows **0.95.0 candidate**: native build run [38092179580](https://github.com/bren-wp/Ghost-FTP/actions/runs/38092179580), Windows Preview QA artifact **11684273785**, produced at 1290 × 852 from the working **0.95.0** React/Tauri UI before the additional macOS security changes on this branch.
- The 0.95.0 Windows QA artifact also contains **720 × 640** and **500 × 620** actual window-size screenshots for key workspaces; these remain to be inspected and checked for clipping/actionability.
- Linux binary/AppImage/DEB/RPM passed build+package smoke in run **38092179580**, Linux artifact **11685010619**. That artifact contains **no GUI screenshot**: Linux pixel parity cannot be inferred from Windows screenshots even though the two builds use the same React frontend.
- A genuine Linux Xvfb-based launch-and-screenshot check at **1290 × 852**, `.github/scripts/capture-linux-premium.sh`, is added to the native workflow with separate `GhostFTP-Linux-x86_64-Preview-QA` PNG/checksum/log artifact. Its success and image quality must be confirmed from a **new run on its actual source SHA** before claiming Linux visual evidence.
