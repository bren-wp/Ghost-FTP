# Ghost FTP 0.99.56 Preview — complete HTTP/cloud download responses

**Publisher:** BRENDIGO — https://brendigo.com  
**Predecessor:** publicly released v0.99.55 Preview

## Reliability and data integrity

- Require HTTP 200 OK for complete-file downloads over HTTP, WebDAV, Dropbox, OneDrive, Google Drive and Box; an unsolicited 206 Partial Content, 204 No Content, 205 Reset Content or other response cannot silently become a complete local file.
- Refuse a Content-Range header even alongside HTTP 200 when no Range request was sent.
- Check Content-Length and byte counters before each chunk write, preventing oversized server payloads from consuming unbounded disk beyond their declared length.
- Flush and sync downloaded cloud staging files and validate expected vs received vs on-disk sizes before the existing safe staged promotion.
- Add Rust unit tests and a real loopback HTTP response fixture covering unsolicited HTTP 206, oversized streams, truncated bodies and overflow.


- Create a fresh, unpredictable staging filename for each whole-file retry, including FTP/FTPS, object storage and cloud adapters; a failed attempt's `.part` file is removed before the next attempt.
- Open whole-file staging files with OS-level exclusive create (`create_new`), preventing accidental truncation of existing files and refusing pre-planted final-component symlinks before any response bytes are written.
- Preserve existing verified-prefix SFTP pause/resume behavior; tests cover separate retry paths, non-clobbering writes and a symlink attack on Unix.

## Remaining limitations

Without a trustworthy remote checksum, HTTP Content-Length validation proves *length*, not full-file cryptographic identity. Some HTTP responses do not supply a Content-Length; these can only be checked against the number of bytes actually received and synced. Independent cloud account tests, cross-platform installation/upgrade, signing and Stable acceptance remain open. The legacy fixed-pixel release requirement remains retired.
