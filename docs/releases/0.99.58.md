# Ghost FTP 0.99.58 Preview — release package structure and safer distribution

**Publisher:** BRENDIGO — https://brendigo.com
**Previous published release:** v0.99.57 Preview
**Channel:** Preview. This is not a digitally signed Stable product edition.

## Improvements

- Validate Windows x64 Portable and NSIS executable optional headers and section layouts, not only MZ/PE magic bytes. MSI remains validated as an OLE compound-file package, not an Authenticode identity.
- Require Linux native and AppImage x86_64 ELF headers with expected architecture, little-endian format, executable/shared-object type and a bounded program-header table.
- Require nonempty ZIP central-directory records, consistent archive directory offsets and real central directory entry signatures. Truncated files and misleading ZIP prefixes fail before asset publication.
- Open packaging inputs with no-follow behavior on supported POSIX hosts, compare on-disk identity with the opened descriptor, and check for mutations during inspection. The ordinary release SHA-256 manifest and remote GitHub asset digest verification remain mandatory.
- Add full-inventory synthetic regression coverage for valid inputs, ZIP corruption and symlink substitution.

## Acceptance

Every test in Ghost FTP quality, Rust workspace, Windows hardening, real FTP/FTPS/SFTP E2E and Windows/Linux native builds must pass for the exact merged SHA. Publishing is handled by the existing checked release pipeline after merge. No historical tags or assets may be changed.

**Limitations:** These are structural preflight checks, not digital signatures, complete installer execution, full archive decoding, package-manager dependency validation or independent Windows/Linux install/upgrade acceptance. Stable requires separately verified publisher signing and production acceptance evidence.
