# Ghost FTP 2.1.1 RC11

Released: 20 September 2026

**More Than Transfer. Total Control.**

RC11 continues the existing native React + TypeScript + Tauri + Rust desktop application. It is a protocol-integrity, UI/UX and production-gating release candidate.

## Highlights

- Fixed the production stacking bug that allowed the main Ghost FTP header and toolbar to render above standalone dialogs and full-screen surfaces.
- Fixed File / Edit / View / Transfer / Server / Bookmarks / Tools / Help menus so they render as real floating popovers instead of breaking the application layout.
- Re-aligned About, Preferences, Site Manager, New Connection and Transfer Center with the current Ghost FTP reference geometry.
- Removed the redundant About heading above the hero panel and restored the Preferences General dashboard to the intended 2-column reference layout.
- Added real protocol E2E acceptance using live FTP, explicit FTPS and OpenSSH/SFTP services.
- Fixed FTP/FTPS data integrity by explicitly selecting binary transfer mode (TYPE I) after login.
- Quick Connect and Site Manager connection tests now use isolated real backend probes instead of changing the active application session.
- Transfer Center is driven by real queue state and live transferred-byte sampling. Simulated transfer scheduling is not presented as functional.
- Secondary views are lazy-loaded and heavy vendor code is split away from the primary application bundle.
- Production dependency audit and native frameless-window architecture checks are release gates.

## Real protocol acceptance

RC11 verifies real operations against local protocol servers in CI:

- FTP: authentication, passive transfer path, mkdir, upload, listing, rename, download byte equality and delete.
- Explicit FTPS: encrypted round trip plus certificate hostname verification and rejection of an invalid identity.
- SFTP: password authentication, encrypted private-key + passphrase authentication, host-key rejection, mkdir, upload, listing, chmod, rename, download byte equality and delete.

Implicit FTPS is not claimed by RC11.

## UI / UX

The RC11 parity pass specifically corrects the defects visible in previous native screenshots:

- no application toolbar over standalone dialogs;
- no clipped or in-flow application dropdown menus;
- correct semantic z-order between menus, modals, command palette, toasts and security prompts;
- cleaner About hierarchy;
- reference-aligned Preferences overview;
- viewport-safe standalone surfaces and dialogs;
- custom frameless Tauri titlebar retained;
- no Chromium/Edge address bar, localhost wrapper or duplicate native titlebar.

The reference artwork remains a visual specification only. The production UI is rendered with real React/Tauri controls and is not a screenshot background or click-map.

## Security & privacy

- No analytics or telemetry SDK was added.
- Connection secrets are not intentionally written to ordinary profile JSON.
- Temporary connection tests do not persist Quick Connect credentials.
- Host-key and TLS identity verification remain enforced.
- The updater verifies signed packages using the configured public key.
- Production signing still requires the protected private signing key to be provisioned in CI. RC11 does not claim signed updater packages unless that gate is actually configured and succeeds.

## Performance

The primary JavaScript chunk was reduced from roughly 2.29 MB to roughly 571 KB before gzip in CI by lazy-loading secondary surfaces and splitting heavy vendor modules.

## Remaining FINAL gates

- Persistent scheduled transfers are not implemented and are not simulated.
- Implicit FTPS is not advertised.
- Installer lifecycle acceptance still requires clean-install, upgrade, Apps & Features uninstall and reinstall evidence on a target Windows machine.
- Production signing/update-signature publication depends on the protected signing secret being available.
- RC11 is a pre-release and is not labelled FINAL.
