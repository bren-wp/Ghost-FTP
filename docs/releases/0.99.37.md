# Ghost FTP 0.99.37 — Windows/Linux scheduling and release reliability (Preview)

**Predecessor:** [v0.99.36](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.99.36), independently recovered from its complete 21-asset draft after full remote SHA-256 inventory verification. Published tags and binaries remain immutable.

## Windows and Linux improvements

- Transfer scheduling uses actual local calendar dates. Invalid date/clock input is rejected and missing daylight-saving local hours never get silently shifted to a different hour.
- Editing an armed schedule's recurrence, date, time or target resets its occurrence checkpoint, preventing stale due times from running a different transfer unintentionally.
- Deterministic regression tests exercise normal schedules, invalid 24-hour clocks, spring DST gap, fall DST repeat and recurring daily/weekly boundaries.
- FTP, FTPS, SFTP and Agent existing transfer safety, host/certificate verification and byte-verified resume logic are retained; any protocol/provider claim still requires real server coverage.

## Delivery improvements

- GitHub release draft uploads can be retried without deleting successfully uploaded artifacts. Matching remote assets are reused only after SHA-256, size and state checks.
- Ambiguous HTTP upload responses (including 422) trigger bounded retries and remote digest checks; conflicting content is rejected without overwriting it.
- Release validation filters exact-source `push` checks, ignoring later skipped secondary workflow runs.
- New README marketing text remains original Ghost FTP branding with **genuine native application captures** for Windows and Linux; screenshots explicitly retain capture provenance and are not misrepresented as 0.99.37 images.

## Packages and acceptance

Windows: Portable EXE, Setup EXE, MSI. Linux: binary, AppImage, DEB, RPM. macOS: existing native and shared Preview packages. Android is retired.

Require exact-head CI quality, Rust tests/Clippy, Go tests, TypeScript/UI, native Windows/Linux/macOS package builds, FTP/FTPS/SFTP localhost roundtrip, security/dead-code scans and release SHA-256 matching before publication. This is **not** a stable-signed release, external-cloud certification or proof of 0% pixel-diff deviation.
