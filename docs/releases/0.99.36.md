# Ghost FTP 0.99.36 — desktop-only project, complete repository audit (Preview)

**Predecessor:** [v0.99.35](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.99.35). This is an unverified Preview source candidate; no new binary or stable release is claimed until exact-SHA CI and real-device tests pass.

## Product platforms

Ghost FTP now maintains **Windows, Linux and macOS desktop applications only**. The discontinued mobile application and its source, Gradle build, automation, release assets and active verification contracts were removed from the repository. Old public tags and released artifacts remain historically immutable; this change does not unpublish old releases or revoke already-installed software.

## Security and dead-code verification

- Maintain Rust/Tauri and TypeScript desktop transfer, credential, UI, capability and update checks; Go installer/runtime tests; and native Swift/macOS security tests.
- No code is automatically deleted merely because a text-only dead-code scanner considers it unreferenced. Preserve dynamic Tauri IPC, Swift selectors, Go callbacks and test harness entrypoints.
- Keep SFTP and Agent verified-prefix transfer safety, FTP/FTPS restart-only fallback, staging integrity and secret-redacted errors.
- Preserve certificate/host-key verification and reject insecure downgrade behavior.
- Replace former multi-platform reference assumptions with **30 Windows and 29 Linux** design references, none certified as pixel-perfect without genuine runtime screenshots.
- Retain externally verifiable protocol E2E for FTP, FTPS and SFTP. Provider-specific cloud authentication, account-scoped operations, large multipart uploads and desktop visual parity require actual credentials, devices and independent live acceptance.

## Required release gates

The exact source SHA must pass source audit tests, `cargo fmt --check`, `cargo check`, `cargo test`, Clippy, desktop frontend typecheck/build, Go tests/vet, Swift checks, localhost protocol E2E, security regression suites, Windows/Linux/macOS package builds and artifact SHA-256 validation.

These source changes do not certify every external FTP server, all authentication combinations, 1:1 pixel parity or production deployment readiness.
