# Ghost FTP v0.95.37 — SQLite and editor-watch stability (development preview)

Published predecessor: [v0.95.36](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.95.36).

## Implemented

- Reuse the existing bundled SQLite database `ghostftp.db` for local state (sync indices, transfer queue ledger and settings). Startup validates `foreign_keys=ON`, uses a bounded 5-second busy timeout and logs if WAL cannot be enabled (rather than silently ignoring an error). No additional external application backend.
- Saved account passwords and private-key passphrases are still protected by the Windows-native or Linux-native keyring. Neither SQLite nor JSON is advertised as a password vault; OS keyring remains the authentication source of truth.
- External editor watcher fingerprints modified local copies using SHA-256 for files up to 8 MiB; equal-timestamp and equal-length edits now upload, and failed uploads retain the previous fingerprint for later retry. Files above 8 MiB use bounded metadata checks to avoid hashing gigabytes repeatedly.
- PowerShell/.NET generated live-sync scripts now respond only to their own `FileSystemWatcher` event identifiers; other PowerShell automation cannot spuriously retrigger sync or have its events drained.

- [ ] TypeScript and UI script generator regression suite, dead-source reachability
- [ ] Real FTP / FTPS / SFTP protocol E2E
- [ ] Windows security, native Windows NSIS/MSI and Linux DEB/RPM/AppImage build, install/uninstall and QA screenshots
- [ ] Android and macOS shared-code compatibility

## Deferred / further acceptance

- Production built-in code editor syntax highlighting, automatic bracket/quote completion and in-file search for PHP/JS/HTML/CSS; existing **external editor** may provide these features.
- Scalable cross-vendor large-file cloud transfers and real authenticated S3, GCS, B2 and WebDAV performance/E2E benchmarks.
- Full 59-screen Windows/Linux pixel-difference acceptance and quantified comparisons with FileZilla.

Existing saved profile metadata remains in compatibility JSON with safe OS-secret redaction. Migrating it to SQLite must be separately designed with tested crash recovery, CLI/backup compatibility and lossless migration; blindly replacing JSON is not secure or safe.
