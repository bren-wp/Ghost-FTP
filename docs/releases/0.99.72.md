# Ghost FTP 0.99.72 Preview — transfer integrity and maintainability

**Status:** Development candidate, not published. Previous canonical release: [v0.99.71 Preview](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.99.71), published 20 November 2026.

## What changed
- Split the 7,574-line Rust transfer implementation into focused integrity checking and regression-test modules without altering transfer API, retry behavior, queue persistence, or signing.
- Reject HTTP responses with ambiguous duplicate `Content-Length` or `Content-Encoding` headers *before* trusting the wire length or promoting a staged download. Normal identity-encoded, single-length HTTP 200 transfers retain their current behavior.
- Preserve existing fail-closed checks for partial HTTP responses, unexpected `Content-Range`, oversized payloads, incomplete downloads and source/destination integrity.
- Add negative regression cases for duplicated wire metadata; preserve all existing transfer, Windows filesystem, FTP/FTPS/SFTP and release-security tests.

## Verification and remaining acceptance
This is **source code under review**, not a verified Windows/Linux release. Merge requires passing exact-head Rust format/check/tests/Clippy, frontend/Go, static security and dead-code scans, native Windows/Linux builds, installer QA and real FTP/FTPS/SFTP E2E. The public tag v0.99.71 must remain immutable. No claims of 1:1 reference matching, independent penetration testing, cloud-provider live accounts, >4-GiB network fault testing, external publisher signing or signed Stable distribution are made.
