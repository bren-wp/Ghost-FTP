# Ghost FTP by Brendigo — 0.99.79 Preview

**Status:** development source candidate. Publication requires successful CI on the merged main commit and a public GitHub Release with complete assets. **Previous public release:** [v0.99.78](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.99.78). **Date:** 22 November 2026.

## Remote Agent background service argument hardening

- Preserve executable and argument boundaries when installing Linux systemd user/system services and Windows logon Scheduled Tasks.
- Quote Linux systemd arguments individually, escaping backslashes, double quotes, percent specifiers and literal dollar signs; correctly preserve configured paths containing whitespace.
- Apply Windows command-line quote and trailing-backslash escaping to task paths and arguments.
- Reject embedded control characters (including newline injection) instead of writing malformed or potentially injected service definitions.
- Add platform-specific quoting regression tests and shared control-character validation tests.

## New operational option

- `ghostftp-agentd service-status` now displays Linux systemd LoadState, ActiveState, SubState and UnitFileState or the Windows Scheduled Task details, without creating a device identity or modifying configuration.
- Linux user-service installation reports inability to create its systemd directory instead of silently ignoring the error. Windows installation reports failure to launch the newly registered task instead of falsely reporting a running agent.

## Verification and limits

Source-level changes and tests are not a substitute for native OS acceptance. Require Rustfmt, workspace tests and Clippy, Windows hardening, FTP/FTPS/SFTP protocol E2E, Windows/Linux native installers, checksums and exact merged-main release provenance. Linux systemd unit syntax checks and real install/start/uninstall trials, plus Windows Scheduled Task argument round-trip tests, remain separate acceptance tasks. Cloud-provider integration, physical fault injection and device-specific credential-vault behavior remain independently unverified.

This is an unsigned Preview candidate, not a signed Stable release. GitHub branch protection remains a repository-administrator responsibility tracked in issue #327.
