# Ghost FTP 0.95.7 — Android SAF cancellation isolation (development candidate)

**Not yet published.** Latest verified public GitHub release when preparing this branch: `v0.95.6`, tagged at `a25403c78cb8d26e0dd57495c23598d81ed2860f`. PR #139 was merged later as `9e1f2cc914f09a613cdaab1a6f49fb01109934a0`. Never move or reuse that immutable public tag.

## Code changes

- Android `CloudTransferCancellation.cancel()` dispatches each SAF provider input/output `close()` independently on a daemon closer. If one provider blocks inside `close()`, another watched handle can still be signaled.
- A deterministic JVM test asserts the second stream is closed despite a simulated first-provider blocked close. Existing tests for UI-safe cancellation, late stream registration and completed-handle cleanup remain.
- Shared source, Android/Go, Windows/Linux desktop, Rust crates, updater metadata and release docs are advanced to 0.95.7, with `previousVersion=0.95.6` and `previousPublishedVersion=0.95.6`.

## Limits and open acceptance

This is a narrow mitigation for #127, not proof that third-party SAF Binder I/O can always be canceled. Android 8–15 physical-device tests, permission revocation, process kill/rotation, 1 GiB/disk-full and non-atomic SAF cleanup still require proof. #126 requires controlled DNS/rebinding/proxy/VPN and real signed-cloud provider success evidence. #128 requires system-browser OAuth PKCE, protected token storage and real account-backed file operations. macOS FTPS/SFTP, notarization and installed-app 75-screen visual comparisons remain unverified.
