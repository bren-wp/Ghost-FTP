# Ghost FTP 0.95.24 — native macOS FTP safety (development preview)

Published predecessor: [v0.95.23](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.95.23).

## Changes
- Swift FTP downloads use private staging and atomic no-replace publication of new destinations.
- Only a regular destination explicitly confirmed through Save Panel may be replaced; symbolic links, directories and special files fail closed.
- Completed FTP transfers that encounter local publication conflicts retain the authenticated control connection.
- Validate ASCII three-digit FTP reply codes in the 100–599 range, with proper separators.
- Unit and real FTP fixture regression tests cover destination collision, symlink rejection, authorized replacement and control-channel synchronization.
- Windows and Linux Tauri installer homepage metadata uses https://ghostftp.com.
- Windows/Linux local file inventory reports metadata failures rather than silently omitting entries; filenames that cannot round-trip through the current UTF-8 IPC representation fail explicitly.
- Local rename/delete refuses root-equivalent targets; Linux chmod checks and refuses explicit symbolic-link and special-file targets before applying permissions.
- Context menus adapt to real viewport and content size, scroll when required and prevent duplicate async action submissions.
- Additional native filesystem and frontend interaction-regression tests were added; final exact-head CI evidence must be checked before considering these changes verified.

## Release blockers
The macOS SwiftUI native implementation lacks trusted FTPS and SFTP engines. Full FileZilla parity, third-party real-server security interoperability, durable transfer queues, native UI/device checks, Apple Developer ID signing and notarization remain required (see [P0 issue #157](https://github.com/bren-wp/Ghost-FTP/issues/157)).
This is unreleased **preview** source documentation, not a production/stable release.
The published v0.95.23 tag is immutable and must not be retargeted. The public website update/download version must be reconciled separately.
