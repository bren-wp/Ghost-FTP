# Ghost FTP 0.99.32 — Windows/Linux secure sessions and native performance (Preview)

**Last published edition:** [v0.99.31](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.99.31). This is a proposed new development Preview; v0.99.31 assets, source tags and checksums remain immutable.

## Functional and security changes under review

- The Windows/Linux Files screen now reflects the real backend session health: unhealthy connections show a warning rather than an incorrect green secure-connection badge; unknown and checking sessions remain neutral.
- Quick Connect does not preserve the submitted plaintext password in React input state after success **or** failure. Server identities and transfers remain real, not concept-image placeholders.
- Grant connections resolve a public issuer address once and use a direct, no-proxy HTTP client. The one-time grant token is not sent via an external proxy. Both manifest and key-install response streams enforce a byte limit even when Content-Length is absent or misleading.
- Imported grant hosts reject control characters, userinfo, URL/path delimiters, excessive lengths and invalid login ports, with focused native Rust tests.
- Windows/Linux status clock no longer wakes up each second in a hidden/minimized desktop window, reducing idle CPU and background activity.

## Validation and limitations

The exact pull-request head must pass TypeScript, Rust tests, native Windows MSI/NSIS, native Linux DEB/RPM/AppImage, Android, macOS and protocol E2E checks before merge. This work does not certify 1:1 pixels against all 59 Windows/Linux concept screens or every UI action on physical devices. FTP remains unencrypted; Linux Secret Service locked/missing-session scenarios and installer upgrades need target-device testing. The existing Linux distribution matrix specifies supported package families and excludes unverified distributions and CPU architectures.
