# Ghost FTP 0.99.67 Preview — source candidate

**Publication:** NOT PUBLISHED. Latest published Preview is [v0.99.66](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.99.66). Changes in new development PR after #294.

## Data protection and reliability work

- Terminal transfer statuses (Done, Skipped, Error, Canceled) cannot be changed by late progress callbacks or stale worker completion. Explicit user Retry can requeue only failed/canceled records.
- Mutation of in-memory transfer state and writing the corresponding SQLite ledger snapshot are serialized to prevent a delayed progress write from replacing the final durable status.
- Concurrent manual Retry invocations are serialized to avoid double requeue or aborting the other retry's worker.
- FTP/FTPS/SFTP automatic retry is tied to one local source-file metadata/identity snapshot across attempts. An altered source cannot silently become the next revision within the same logical upload.
- Added native regression tests for cancel/completion races, incomplete success, persistent terminal history and safe manual retry; expanded whole-repository security-source contracts.
- Fix startup WebView white/black flashes by constructing the native main window hidden, adding a synchronous HTML theme fallback, and revealing only when the React shell mounts; restrict the Tauri show capability to the single main window. Added automated startup-regression checks.
- [Startup first-frame Windows/Linux acceptance checklist](../qa/STARTUP_FIRST_PAINT_0.99.67.md) remains unverified on installed hardware.

## Limitations and release gates

The source identity check detects ordinary file changes but is not a cryptographic checksum. FTP no-overwrite rename races and remote temporary leftovers remain server-dependent. The 4+ GiB, 1/4/8 concurrent transfer fault-injection matrix, physical Windows Credential Manager and Linux Secret Service reconnect tests, signed packaging and installed-app interaction must be evidenced separately.

**This is an unpublished Preview candidate, not proof of a stable release or full independent penetration test.** Do not publish until exact-head CI and required live QA pass.
