# Ghost FTP 0.20.3

Release cycle: **0.20.3 patch release candidate**

Cycle date: 1 October 2026

0.20.3 follows published 0.20.2. This document does not assert publication: only an immutable `v0.20.3` GitHub Release at the verified source SHA with the required assets establishes the release.

## Changes in this cycle

### Shared file-browser async action reliability

- Confirmation and prompt dialogs in `@ghostftp/file-ui` now await asynchronous actions instead of closing immediately after dispatch.
- Rename, new-folder, chmod and delete operations are serialized while in flight, preventing accidental double submission.
- Backdrop, Escape and Cancel cannot dismiss a file-operation dialog while its mutation is still running.
- Failed filesystem mutations keep the dialog open for retry.
- In-dialog failure feedback is intentionally generic so raw backend details are not exposed; the existing file-pane error surface keeps the detailed redacted/normalized operation error.
- Redundant prompt autofocus logic was removed; the shared dialog hook remains the single focus-entry, focus-trap and focus-restoration implementation.
- Interaction-contract checks now guard the shared file-ui async locking and failure-propagation behavior.

### Release documentation alignment

- Android release documentation now matches the implemented artifact policy: the production `com.ghostftp.android` APK is explicitly unsigned and named `.apk.unsigned`.
- A separate non-debuggable installable preview remains CI evidence for clean-install, reinstall and launch smoke. It is not presented as the canonical production APK.

### Version and release integrity

- Advance canonical metadata to 0.20.3 with previous version 0.20.2.
- Advance Android `versionCode` to 211032.
- Keep version tags immutable; published `v0.20.2` remains unchanged.
- Keep documentation screenshots pinned to the newest published release until release-proven replacements exist.

## Publication requirements

The exact source intended for `v0.20.3` must pass Ghost FTP quality, Ghost FTP protocol E2E, Ghost FTP native build, Ghost FTP Android and Validate Windows hardening on the same head SHA.

The canonical release must contain non-empty Windows portable/NSIS/MSI assets, Linux binary/AppImage/DEB/RPM assets, Android unsigned-production/installable-preview artifacts, source/documentation archives, native-QA evidence and SHA-256 checksums.

## Stable status

0.20.3 remains in the pre-1.0 version train. Passing automated release gates does not by itself claim 1.0/FINAL product acceptance.
