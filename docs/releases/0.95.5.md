# Ghost FTP 0.95.5 — cross-platform cloud credential privacy (development candidate)

**Development source only. Not a published release.** Latest independently confirmed GitHub Release at cycle start: [v0.95.4](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.95.4), 12 October 2026. Existing public release tags are immutable.

## Implemented source changes

- **Windows and Linux:** A short-lived signed provider URL is itself an access credential. Production diagnostics now suppress the entire signed object URL when signature parameters are present, including Amazon S3 / Cloudflare R2 / Google Cloud Storage / Azure Blob SAS forms. Existing diagnostic sanitization and limit checks remain. Executable TypeScript regression cases cover S3, GCS, Azure and R2.
- **Android:** Clear the signed object URL input before launching SAF file pickers, never display the bucket/account hostname in transfer status; if a newly created SAF download destination is returned after Activity recreation destroyed the non-persisted signed authorization, attempt to delete it immediately and warn explicitly when the provider refuses.
- **macOS:** Remove signed URLs from SwiftUI field state immediately after validation and before displaying an open/save panel, even if the user cancels selection. Transfer status does not show hostnames. No signed URLs are written into saved state.

## Dead-code, stability and platform assessment

- Windows/Linux: executable `npm run check:dead` TS module graph + Rust module graph and operational script reachability, TypeScript `noUnusedLocals`, Rust build/tests and protocol E2E.
- Android: private Kotlin symbol scan, Gradle unit/lint/APK checks and emulator instrumentation. Static scan alone does not prove absence of lifecycle or reflection-driven dead paths.
- macOS: private Swift symbol scan, Swift unit tests and release build. No claim of production FTPS/SFTP transport feature equivalence with Windows/Linux.
- A review of current 75-screen design traceability shows each reference as **pending** visual acceptance, not a verified 1:1 installed screenshot. Missing actual baseline files/device and independent macOS mockups block pixel certification.
- This audit does not assert a complete application security review or guarantee that every connection works perfectly. Protocol provider/permissions/device labs and real packaged-app click-through remain necessary.
