# Ghost FTP 0.30.1

Ghost FTP 0.30.1 follows the published canonical 0.20.10 release and starts a broader hardening cycle without rewriting any existing tag or release.

## Changes

- Makes Android FTP/FTPS staged uploads fail closed when preserving an existing remote target.
- Requires a successful parent-directory existence check before treating an FTP upload target as absent.
- Requires an explicit SFTP `lstat` no-such-file result before treating an SFTP upload target as absent.
- Refuses promotion when a target appears during an in-progress upload instead of silently overwriting it.
- Surfaces backup-restore failures with the preserved remote backup path instead of hiding a failed recovery attempt.
- Adds Android regression coverage for remote parent/name splitting and CI contract guards that reject the previous ambiguous backup-rename fallback.
- Centralizes FTP/FTPS/SFTP temporary-file promotion, backup, rollback and cleanup invariants in one testable fail-closed staged-replacement transaction.
- Adds deterministic JVM regression coverage for absent/existing targets, existence-check failures, backup failure, promotion failure, rollback recovery, rollback failure, temporary cleanup, late target appearance and SFTP error classification.
- Protects existing local files during desktop Overwrite downloads by streaming whole-file backends into transfer-specific sibling staging files, then using backup/promotion/rollback only after the backend completes.
- Extends the same protection to Ghost FTP Agent whole-file fallback while leaving the Agent delta path on its existing hash-verified temporary assembly flow.
- Adds Rust regression coverage for staged replacement paths and verifies that pre-promotion failure leaves the existing local destination untouched.
- Makes desktop SFTP Rename conflict probing fail closed: only a protocol-proven missing path is considered free; permission, connection, timeout and other probe failures now abort candidate selection.
- Adds deterministic Rust coverage for original-path absence, candidate collisions, permission-denied target probes and connection-failure candidate probes.
- Makes desktop directory uploads fail closed when a local source entry cannot be statted instead of silently omitting that file or subtree from the queued upload.
- Reuses the same source-tree metadata guard in Agent Bridge directory-upload preflight so approval counts cannot describe a different tree from the transfer engine.
- Updates central version progression rules so an explicitly planned forward SemVer jump is allowed only when the new version is strictly newer and `previousVersion` matches the exact published base.
- Cancels superseded Windows hardening runs per PR/ref so obsolete commits do not keep consuming Windows runners.

## Acceptance

The exact PR head must pass Ghost FTP quality, Ghost FTP protocol E2E, Ghost FTP native build, Ghost FTP Android and Validate Windows hardening before merge. Stable publication remains tied to the exact verified `main` SHA and an immutable `v0.30.1` tag.
