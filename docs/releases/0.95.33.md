# Ghost FTP v0.95.33 — Windows/Linux safety and premium usability (development preview)

Published predecessor: [v0.95.32](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.95.32).

## Changes

- SFTP directory listings refuse unsupported names, duplicate names and oversized filename inventories before returning them to UI, sync or conflict logic.
- Selected directory symlinks and unsupported nodes cannot implicitly turn into ordinary file transfers.
- When overwrite prompts are disabled, two sources sharing one basename cannot silently overwrite each other in the same transfer batch.
- File Manager and Transfer Center diagnostics now pass through existing sensitive-text redaction.
- Improve progress-bar accessibility and stabilise time-based transfer-history filtering.
- Main README retains seven real Windows native screenshots with corrected manifest provenance.

## Verification

- [ ] Final exact-SHA frontend, dead-code reachability, Rustfmt, Cargo/Clippy and Rust tests
- [ ] Real FTP/explicit FTPS/OpenSSH SFTP protocol E2E
- [ ] Windows native NSIS/MSI + Linux AppImage/DEB/RPM builds
- [ ] Android/macOS shared-code compatibility
- [ ] Real installed-desktop visual comparison at 1290×852, smaller windows and DPI scaling

Known limitation: the SFTP library currently constructs its full raw listing before the application's entry/name-byte inventory check runs. This check prevents misleading or excessive displayed listings, but is not a complete upstream memory bound. Remote SFTP multi-path deletion is not atomic. Neither pixel-perfect visual acceptance nor full FileZilla-equivalent capabilities are claimed without testing.
