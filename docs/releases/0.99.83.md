# Ghost FTP by Brendigo — 0.99.83 Preview

**Status:** development candidate; not published. **Previous public release:** [v0.99.82](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.99.82), published 23 November 2026. **Date:** 24 November 2026.

## Sites and connection workflow

- Connected filter reflects real session profile identifiers, and Open session focuses a live connection instead of opening a duplicate.
- Clear search, reset filters, result counts and editable site names make saved-site management faster.
- Natural sorting, consistent category counts and finite last-used timestamps are shared read-only selectors. Credentials are excluded from search.
- A synchronous action guard prevents overlapping Site Manager profile mutations. Password visibility is scoped to the displayed draft; switching sites clears visibility and metadata editing. Deletion rechecks live sessions before proceeding.
- Responsive header and search, keyboard focus outlines, accessible icon controls and sort-direction labels improve the existing branded interface.
- Regression checks cover selector behavior, privacy, invalid dates, connected filtering, and wiring.

## Follow-up audit and CI repair

- P1 (Agent config staging): a failed exclusive open previously entered the generic cleanup path and could unlink a staging file not owned by that writer. Open before cleanup ownership begins; close the owned handle before rename. Regression tests preserve existing configuration and foreign staging bytes and verify a later save succeeds.
- P2 (Sites): selected and draft profile IDs must match before rendering connection details or revealing a password. Prevent stale-draft saves and editing fields during a native mutation.
- P2 (Linux matrix): update the source contract to verify the extracted production selector and its real row wiring rather than requiring inline filtering in the dialog. Existing keyboard, deletion, native visual and protocol checks remain intact.

The Agent quota, admission lock and per-controller cap were already present; no duplicate fix is claimed. Native GUI acceptance and production signing remain separate gates.

## Agent configuration validation

- P1 (availability / configuration integrity): enforce the 1 MiB input limit on actual reads, not only the pre-read metadata. Reject non-regular opened files and distinguish missing paths from inspection failures. A dangling symlink is no longer treated as a missing configuration.
- Validate the existing 128-peer and 1 MiB limits before staging a new configuration so an invalid save cannot replace a previously readable configuration.
- Added regressions for oversized input, rejected saves preserving original bytes, and dangling symlinks on Unix. Source change: [49169d0](https://github.com/bren-wp/Ghost-FTP/commit/49169d0f7dc7ecbd2ea2341cbc83df45938abe77). Exact-head CI and native acceptance are pending. These changes do not establish full race-free filesystem access or parent-directory containment.

## Unix configuration file opening

- The config reader now opens the final pathname component with no-follow and nonblocking flags on Unix, then validates the opened handle as a regular file. This closes the final-component symlink follow and FIFO blocking gaps between the preflight metadata check and open.
- Added two Unix regressions that exercise the actual open helper without relying on the preflight check, and isolated the legacy migration test in a unique temporary directory. Source: [5092242](https://github.com/bren-wp/Ghost-FTP/commit/50922420940f517e06a17c8f3d8bc5dce266be02).
- Windows handle-level reparse-point checks, parent-directory races, hard links and actual Windows Scheduled Task stop verification remain open. No claim of complete filesystem hardening or native acceptance is made.

## Transfer staging integrity

- P1: the shared download durability check now validates type and exact byte length on the opened handle, rather than relying only on an earlier pathname inspection. On Unix the open rejects final-component links, is nonblocking, compares device/inode and refuses additional hard links. On Windows it opens reparse points without following them, rejects reparse attributes and checks creation/write timestamps.
- Existing no-replace promotion, original-file backup and rollback behavior remain unchanged. Added a Unix regression ensuring a hard-linked delta staging file cannot replace an existing destination and unrelated bytes remain untouched.
- Source: [ad88d96](https://github.com/bren-wp/Ghost-FTP/commit/ad88d96e1615d258579d326bbe277b4b3b8801b3). Native CI remains required. Windows timestamps are not a unique file identity; Windows hard-link checks, parent-directory containment and the race between verification and pathname-based promotion remain open. FTP server-side atomic replacement limitations are unchanged.

## Follow-up: Windows hard links and Linux directory handles

- Windows staging verification now checks the actual opened file's hard-link count using GetFileInformationByHandle and rejects any count other than one. The existing hard-link regression now covers both Windows and Unix. [c816a04](https://github.com/bren-wp/Ghost-FTP/commit/c816a04ec0f4eda650ece9567a7bd987ab3bb246).
- All shared staging durability checks re-inspect the pathname after syncing. Unix checks the device, inode and link count again; Windows checks reparse attributes and timestamps. This narrows but does not eliminate the verification-to-promotion race.
- Linux no-replace sibling moves use a single pinned directory descriptor and renameat2, including backup/restore moves. O_PATH avoids requiring directory read access. A regression replaces the parent pathname after opening the directory and verifies the operation stays within the pinned directory and does not overwrite an occupied target. [3bffcf9](https://github.com/bren-wp/Ghost-FTP/commit/3bffcf93b48fd2c5135445118b5b2871b056afe2), [40d66fb](https://github.com/bren-wp/Ghost-FTP/commit/40d66fb4551d483c3e60ad30ccd0c16fcc250e72).
- Remaining: a single trusted directory handle throughout the full transfer/promotion/rollback lifecycle, safe Windows directory-handle-relative promotion, Windows file identity checks beyond timestamps, and source-entry substitution after verification. Native CI must verify these changes before publication. No claim of complete TOCTOU protection.

## Linux pinned overwrite transaction

- Linux sibling overwrite promotion now pins one directory descriptor for the entire final transaction. Entry inspection uses fstatat with AT_SYMLINK_NOFOLLOW; backup, promotion and rollback use renameat2 relative to that same descriptor, and backup cleanup uses unlinkat after a file-identity check. Uncertain recovery entries are preserved rather than knowingly restored or deleted. Existing backup collision and no-overwrite behavior is retained.
- Added a regression that replaces the original parent pathname after pinning and verifies promotion and cleanup do not modify the replacement directory's destination or backup. [e9da28f](https://github.com/bren-wp/Ghost-FTP/commit/e9da28f75494d2869a320e2a8a5cd2ab865c7b4d), [9d32bf7](https://github.com/bren-wp/Ghost-FTP/commit/9d32bf788cd332b0cdc7613c05b6a127d264f281).
- Repaired both formatting differences reported by the [Rust workspace job](https://github.com/bren-wp/Ghost-FTP/actions/runs/45486410853/job/138772909327); the formatting gate is unchanged. The new source still requires exact-head verification.
- Limits: the descriptor is pinned at final promotion, not at the start of the network transfer. Initial parent resolution, same-directory entry substitution between metadata and mutation, failed-transfer staging cleanup, Agent delta replacement and Windows handle-relative promotion remain open. No claim of complete TOCTOU protection or native acceptance.

## Download parent lifetime and Agent integration

- DownloadParentGuard keeps an open directory handle from worker admission across retries, completion and cleanup. Linux compares device/inode; Windows compares volume serial/file index from open directory handles. A detected parent change stops the worker and avoids pathname-based cleanup in the changed directory. A cross-platform regression replaces and restores a parent and checks detection.
- Linux whole-file overwrite and no-replace promotion reuse a cloned original descriptor in the blocking commit worker; the clone stays alive even if the async caller is aborted. Agent full-download promotion also uses its initially opened descriptor. Agent delta verifies parent identity before basis inspection, patch creation, reassembly, commit and cleanup; fallback checks the original parent again.
- No /proc/self/fd path is passed to backend I/O: canceled async tasks may leave blocking workers running, so such paths would risk descriptor-number reuse. Existing network backend writes, some cleanup, and delta atomic rename still use pathnames. Same-directory entry substitution and changes during a path-based operation remain possible. Windows final handle-relative rename remains open. No full TOCTOU or native acceptance claim.
- Repaired three Rust formatting differences from [Rust workspace CI](https://github.com/bren-wp/Ghost-FTP/actions/runs/45486904206/job/138774628197); formatting gate remains unchanged.
- Source: [035eea6](https://github.com/bren-wp/Ghost-FTP/commit/035eea62fa4331dc9ba267958f8b5593d64d9b66), [8eebc39](https://github.com/bren-wp/Ghost-FTP/commit/8eebc39fe28118e326a9feac3a76cb42f2f2d0d7), [aa8795f](https://github.com/bren-wp/Ghost-FTP/commit/aa8795f4284dd3cd05bb3df4cb8e5629456862f5), [3818fd6](https://github.com/bren-wp/Ghost-FTP/commit/3818fd6d98407b87aa158a70a505867e29de376f). ## Resumable download staging handles

- SFTP and Agent download resume now use a shared non-truncating read/write staging open. Unix rejects final-component symlinks and non-regular files, avoids blocking on FIFOs and checks the open file's hard-link count. Windows opens without following reparse points and checks the opened file's type, reparse attributes and hard-link count. A rejected open is classified as unowned so generic cleanup does not remove it.
- Both download paths reuse the validated file handle for prefix verification, resizing, seeking and streaming instead of reopening the pathname between verification and truncation. The existing Agent upload prefix wrapper remains in use. Added Unix symlink and Windows/Unix hard-link regression tests protecting original bytes and the rejected staging entry.
- Repaired the actual Rust formatting differences reported by [CI](https://github.com/bren-wp/Ghost-FTP/actions/runs/45487337106/job/138776173213); the gate is unchanged. Source: [cebdbdf](https://github.com/bren-wp/Ghost-FTP/commit/cebdbdf271b9a462afc001bb0389dcc8d183ae1f), [2fc7ff2](https://github.com/bren-wp/Ghost-FTP/commit/2fc7ff2e77f54f867cce890600f1209f64730d37).
- Limits: an existing ordinary staging file is still accepted for resume/restart; ownership across worker lifetimes is not yet authenticated. Parent-relative opening, source-entry substitution before promotion, full Agent delta handle-relative I/O, Windows native handle-relative rename and ownership-safe cleanup remain open. Exact-head compilation and native tests are required.

## Verified file identity at final promotion

- The shared durability verifier returns its still-open staging file. The main download worker carries that handle into promotion rather than discarding it, and Agent full download hands over the actual synced writer handle. Linux holds a cloned file handle and the originally pinned directory descriptor together in the blocking promotion worker. Device, inode, link count, regular-file type and size are compared with the pinned entry before moving the original and again before publishing the stage. Windows compares the live handle with a reopened no-follow staging handle before the existing pathname-based move.
- Agent Skip/Rename cleanup checks the retained file identity; on Linux it inspects and unlinks relative to the original directory descriptor. A failed durability/identity check no longer triggers automatic pathname deletion by the main worker. Added a Linux regression substituting an equal-length stage after verification, then checking that promotion and cleanup preserve the original destination, the replacement entry and the verified data.
- Repaired two reported Rust formatting differences from [CI](https://github.com/bren-wp/Ghost-FTP/actions/runs/45487738912/job/138777557642). Source: [c8b2153](https://github.com/bren-wp/Ghost-FTP/commit/c8b2153257a444040430bde0b535732915436f35), [248f5c5](https://github.com/bren-wp/Ghost-FTP/commit/248f5c57cf0699e0798247ea00f5b0de9b41d976), [76488f7](https://github.com/bren-wp/Ghost-FTP/commit/76488f73f6d055e3fc9a3bbd788f1618d86a4fe7).
- Limits: ordinary protocol stages are reopened for durability verification, so the original writer identity is not yet established for every backend. Linux name-based rename/unlink still has a same-directory check/use race, and the live inode can still be modified. Windows native handle-relative rename/delete, complete Agent delta ownership and cleanup, and the earlier parent-relative open gaps remain open. Failed verification can intentionally leave a staging entry for recovery. Native and exact-head CI remain required.
