# Ghost FTP v0.99.64 Preview — Agent delta-upload integrity

**Publisher:** BRENDIGO · https://brendigo.com  
**Development candidate:** v0.99.64 Preview · **Last published edition:** v0.99.63.

## Priority changes

- The Agent delta-upload planner now creates its local patch exclusively instead of using `File::create`. A colliding ordinary file or planted symlink is preserved.
- Planner errors are distinguished by ownership: failure to create the patch or an unverified worker join never authorizes deleting a potentially unrelated file.
- Each delta `WriteChunk` response must acknowledge precisely the chunk's byte length; short and oversized replies fail closed.
- After `DeltaDone`, the controller requests fresh remote metadata and verifies the daemon's reused-byte count and reconstructed length against the planned file size.
- Failed patch cleanup checks the entry is a regular file, not a symlink or special filesystem entry.
- Regression tests guard collision, symlink and acknowledgement/integrity cases.

## Compatibility and acceptance

This update does not migrate profiles, change connection IDs, reset credentials or alter OS secret-vault storage. The v0.99.63 saved-profile reload on app launch remains in place.

Before publication, exact-head Rust fmt/tests/Clippy, TypeScript build, security/dead-code audits, FTP/FTPS/SFTP E2E, Windows hardening, Windows/Linux native builds and immutable Preview release governance must all pass.

These tests do not establish universal cloud-provider correctness, hostile local-process TOCTOU resistance, installed-machine upgrade acceptance, full crash/power-loss recovery, or signed Stable binaries.
