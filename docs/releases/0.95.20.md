# Ghost FTP 0.95.20 — FileZilla SFTP key authentication import

## Implemented in the unreleased development candidate

- FileZilla `Logontype=5` (key-file login) on an SFTP profile now preserves the selected `Keyfile` path in Ghost FTP's existing private-key authentication field; it never opens the private key at import time.
- Stale `Keyfile` paths left by FileZilla after switching to password mode cannot change authentication. Key paths on FTP/FTPS profiles are ignored.
- PuTTY-specific `.ppk` keys are not automatically enabled as usable OpenSSH keys; the import preview warns to convert to a compatible format. Missing/invalid key paths are also reported. Password data from the FileZilla XML is never imported.
- Rust unit tests cover SFTP key migration through ConnectionProfile, stale keys, FTPS key isolation and unsupported/missing key cases.

## Required verification

Quality, live local FTP/FTPS/SFTP protocol E2E, Windows/Linux installer and genuine screenshot QA, Windows hardening, Android, and macOS must all pass at the same exact commit before merge or publication. SSH private-key compatibility and real FileZilla export interoperability across OS/device remain partial, not proven.
