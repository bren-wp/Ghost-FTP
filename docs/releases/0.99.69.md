# Ghost FTP 0.99.69 Preview — stronger source-integrity checks

**Publication:** Source candidate until the canonical [v0.99.69 release](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.99.69) actually appears with verified native assets. Previous published version: [v0.99.68](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.99.68) (15 November 2026).

## Safer staged FTP, FTPS and SFTP uploads

- FTP/SFTP upload source snapshots now include an additional bounded SHA-256 digest, checked on the same source pathname and file identity before each transfer attempt and before promotion.
- Small files (up to 64 KiB) are hashed in full. For larger files, the digest covers distinct 64 KiB windows at the beginning, middle and end; additional local I/O remains bounded even for files larger than 4 GiB.
- The new guard detects common same-length source modifications where the modification timestamp was restored and previously matched the metadata-only snapshot, preventing promotion in that detected case.
- Source-window verification also guards automatic retries without silently treating a newly edited file as the original transfer source.

## Automated regression coverage

- Same-sized content rewrite followed by restoration of the original modification time.
- Sparse **4 GiB + 16 bytes** Linux source: 64-bit length metadata, bounded sample verification, modification at end of source and rejection before promotion. The sparse test does not send 4 GiB over the network or claim to validate real-server throughput.
- Existing protocol E2E, concurrency, transfer ledger, Windows filesystem, UI, versioning, privacy, audit, signing and native packaging gates remain required.

## Important security and acceptance limitations

**Sampled hashing is not a complete file checksum.** Mutations outside the sampled regions, rapid concurrent writes, malicious timestamp/device metadata manipulation and server-side corruption can remain undetected. The local digest is not compared with remote contents. Always use a full SHA-256 comparison and a controlled server when independently validating transfer integrity. Existing FTP rename-overwrite races, staging leftovers, ambiguous acknowledgments and provider-specific cloud behaviors are still documented limitations.

**Not certified:** Full 4 GiB+ network transfers at 1/4/8 parallel workers under injected faults, physical Windows/Linux credential-vault reboot and locked-store testing, genuine installed-app user acceptance, publisher identity signing and Stable distribution. No source-level test should be represented as complete production acceptance.
