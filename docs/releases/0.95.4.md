# Ghost FTP 0.95.4 — Android SAF download integrity security candidate (NOT PUBLISHED)

Latest verified public GitHub release: **v0.95.3** (12 October 2026), immutable commit `1e79375e97ab2efbaa4ebaa2c91302908074d370`. This candidate changes real source and does not rewrite any tag.

## Security change: Android saved-document readback

- A successful network download is staged in app-private cache and checked against a provider's optional S3 SHA-256 header, plus the actual HTTP content length when known.
- After closing the SAF output stream, the app now reopens the **actual destination document** through Android ContentResolver, streams it without a second full memory copy, and requires identical byte count and constant-time SHA-256 digest versus the verified staging file.
- A provider that silently truncates, modifies, appends bytes, or cannot read back the saved file fails closed rather than showing a false success. Existing failure cleanup attempts to delete the newly created SAF document and warns if the provider refuses.
- The document picker explicitly requests read and write URI grants for this check. Signed cloud URLs remain ephemeral and no secret is added to saved state or diagnostics.
- Added isolated JVM regressions for exact/zero-length documents, truncated/oversized outputs, same-length corruption, invalid checksums and cancellation.
- **Android and macOS SSRF defense in depth:** Both public-DNS/peer filters reject RFC 9637's non-global documentation prefix `3fff::/20`, IANA benchmarking `2001:2::/48` and deprecated ORCHID `2001:10::/28`. Android also revalidates ASCII hostname syntax within OkHttp's actual DNS hook, independent of initial signed-link parsing. Added platform unit tests. Controlled DNS/proxy/VPN and real-provider labs remain unverified under #126.

## Limitations and outstanding security acceptance

Readback cannot guarantee durable physical storage against a provider that lies on **both** reads and writes, nor can it supply atomic replacement for SAF implementations lacking transactions. Real provider tests on Android 8–15, permission revocation, low-storage/disk-full, rotation, app death and cancellation remain **not completed** and required under reopened #127.

Reopened #126: controlled DNS/proxy/VPN/rebinding lab plus real S3/GCS/Azure compatible provider results are required despite connection-bound IP policy. Reopened #128: Android/macOS OAuth account login, PKCE, secure refresh token storage and actual browsing remain **unimplemented**. This change does not implement them.

Windows/Linux/macOS behavior is unchanged by this Android-specific safety patch aside from shared version metadata and documentation. All six exact-head workflows, packaging and physical-device acceptance must be verified before merging or publishing. Do not advertise full 75-screen pixel parity or stable FINAL.
