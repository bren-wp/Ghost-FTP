# Ghost FTP 0.99.54 Preview — object-store download integrity

**Publisher:** BRENDIGO — https://brendigo.com  
**Previous published release:** v0.99.53 Preview  
**Channel:** Preview; a PR candidate, not a published release until exact-SHA CI and native acceptance succeed.

## Transfer Engine 2.0 improvements

- The S3/object-store download path derives expected object size from the actual `GET` response's `ObjectMeta`, instead of trusting an earlier queued listing estimate.
- Each streamed object chunk is checked for checked-add integer overflow and excess bytes before writing to local staging.
- End-of-stream checks require received bytes, expected response size and written file size to match exactly.
- Staging contents are flushed and `sync_all` completed before the download manager promotes the finished file.
- New Rust regression tests exercise exact-length, truncated, oversized, zero-byte and overflow cases.
- The overwrite destination and its recovery backup remain governed by existing no-replace staged-promotion logic.

## Limitations

This validates **length**, not a remote SHA-256 checksum. Strong end-to-end content identity requires a trusted hash from both source and destination. Live cloud provider tests, large-file stress, app-interruption recovery, Windows/Linux installer QA, code signing and all 59 independent reference comparisons remain open. CI must pass before merge; do not retarget immutable tags.
