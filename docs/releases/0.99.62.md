# Ghost FTP v0.99.62 Preview — secure Agent delta transfers

**Publisher:** BRENDIGO · https://brendigo.com  
**Current development candidate:** v0.99.62 Preview · **Previous published version:** v0.99.61

## Prioritized improvements

1. The shared controller/daemon delta engine at `ghostftp-agent-proto/src/delta.rs` now creates output exclusively. An existing file or symlink is never truncated or deleted on error, and incomplete files are cleaned up only when created by this invocation.
2. The desktop Agent delta path verifies reconstructed on-disk byte counts and durability and promotes through the rollback-safe `promote_staged_download` path, preventing direct rename over non-regular destinations or unverified data.
3. Untrusted Agent delta chunk lengths are validated against each remaining requested range before writing.
4. Agent patch files are exclusively created and only locally owned patch/output paths may be cleaned up on failure.
5. The remote Agent daemon validates delta targets, checks reused-byte counters for overflow, and never deletes an unowned output after exclusive creation fails.
6. Shared staging and local promotion logic is extracted into `transfer/download_staging.rs` to simplify maintenance across FTP/FTPS/SFTP/cloud backends.
7. Regression cases and static security contracts protect the new behaviour without changing user profile schema, OS-vault credentials, connection IDs, or Tauri command APIs.
