# Ghost FTP 0.99.49 Preview — OAuth token response hardening

**Author:** Brendigo — https://brendigo.com  
**Previous public release:** v0.99.48 Preview (15 Windows/Linux/source/docs/checksum assets)  
**Status:** Preview candidate. Publication requires successful exact-source CI, package verification and post-release SHA-256 acceptance.

## Security and reliability fixes

- Prevent integer overflow on provider-supplied `expires_in` values while computing OAuth access-token expiration; preserve existing expiry behavior for ordinary and negative durations.
- Reject OAuth token responses that omit or contain only whitespace in the access token. Rejecting unusable credentials prevents false-success login state.
- Normalize blank refresh tokens to absence so an existing valid refresh token survives refresh responses that omit or blank the value.
- Change the local OAuth authorization callback message to indicate a pending token exchange rather than claiming a completed connection prematurely.
- Add Rust unit regression coverage for these cases; retain HTTPS, PKCE/CSRF state, no-redirect bearer endpoint restrictions and OS credential vault storage.

## Distribution and acceptance limits

The active product targets Windows x64 and Linux x86_64. 15 required release artifacts and the optional all-or-nothing signed-updater group must be checked against SHA-256. Prior tags and bytes are immutable; historical macOS releases remain untouched.

Independent validation remains necessary for real cloud provider refresh/revocation, large multi-transfer recovery, credential-store behavior on devices, hostile-local-client tests, 59 Windows/Linux concept screenshot comparisons, accessibility, and publisher signing. A passing static audit is not evidence of complete production security or 1:1 visual parity.
