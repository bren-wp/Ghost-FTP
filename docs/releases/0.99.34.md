# Ghost FTP 0.99.34 — Windows/Linux transfer integrity and privacy audit (Preview)

**Published predecessor:** [v0.99.33](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.99.33). Published assets and tags must not be rewritten. This edition is source under review until exact-SHA GitHub Actions and release gates succeed.

## Windows and Linux correctness fixes

- SFTP download reads the source's reported byte length, synchronizes the staging file to disk, compares the received and persisted byte counts and rechecks source length. An incomplete or changed-length file is refused **before** the finished staging file could replace the existing local destination.
- SFTP upload now verifies the actual sent byte count against both the originally opened local file and the remote server's reported destination size. A shorter-than-advertised response is an error, not a green Done status.
- FTP and explicit FTPS downloads synchronize staging and require exact received/persisted byte counts; when SIZE is available, remote server length is checked both before and after the transfer. FTP and FTPS uploads verify the sent count.
- Shared Transfer Manager completion no longer fabricates 100% progress from the guessed source size, and an unknown initial size becomes the actual observed byte count. Known-size mismatches are errors.
- Server- or cloud-origin errors may echo temporary credentials. Final transfer diagnostics are now mapped to safe error categories **before persistence in the local transfer ledger**; neither bearer tokens nor signed URLs should be written as failure text.
- Added Rust regression tests for truncated, oversized and zero-byte transfers, sizes above 4 GiB without allocating huge files, unknown initial size and sensitive error reflection. Repository-wide security source checks require the guards.

## Protocol acceptance boundaries

Live local FTP, explicit FTPS and SFTP localhost integration exercises authentication, binary upload/download, boundary sizes, resume/abort and host-key/TLS trust paths. These tests are genuine servers and must pass on the exact release source. HTTP download, WebDAV, object storage and cloud/SaaS adapters are subject to the static code inventory and existing Rust/TypeScript checks but **cannot be claimed fully end-to-end tested on real remote accounts without provider credentials and dedicated fixtures**. HTTP is intentionally read-only.

All Windows x64 NSIS/MSI/portable and supported Linux x86_64 DEB/RPM/AppImage/native packages must pass real native builds; the full developer release train remains Preview until separately documented platform acceptance gates are met. Windows/Linux packages remain installable without purchased code-signing certificates, while cryptographically signed automatic updates remain signature-verified.

### Shared cross-protocol integrity

All non-Agent downloads (including HTTP/WebDAV/object storage/cloud/SaaS) now have a common last-mile check before local destination replacement: the staging file must be regular, byte length must match the actual transfer counter, and its content is flushed to disk. This reduces partial-file promotion across backends without claiming a remote checksum when no trustworthy source size or hash is available.
