# Ghost FTP 0.95.22 — Android 16-screen native reference UI (preview candidate)

This version is an **explicit preview candidate** pending automated publication and release-artifact verification. It must not be described as fully pixel-matched, production-stable or already published. Previous published version: [v0.95.21](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.95.21).

## Source changes actually implemented

- User reference manifest documents both 2026-10-16 composite images and their SHA-256, with 16 separate screen acceptance entries. No generated or fake Android screenshots are claimed as installed app captures.
- Main Android Activity changes from the old permanent 64dp left rail to a full-width phone viewport with a navigable 260/280dp slide-over drawer on phones under 600dp. Tablet rail remains docked.
- Phone title bar is 52dp high. Five real Files actions are docked at the bottom; secondary commands use the More menu. Existing remote upload/download/create/delete/rename controllers are retained.
- Files shows the actual remote listing plus a separate, strictly app-owned local downloads browser rather than fictional system-wide directory access.
- Sites now has a searchable live SavedSiteProfiles listing and functional Add/Edit route. Credentials remain unsaved; destructive operations retain confirmation and failure handling.
- Android uses the user-approved violet accent palette while the Windows/Linux desktop retains its existing blue brand tokens.
- New regression constraints check mobile overlay geometry, navigation and real file action wiring.

## Outstanding before a 1:1 or production claim

This release is a **partial** 16-screen visual implementation. Splash tagline animation, Connect detail view, actual transfer queue/detail, cloud accounts, bookmarks, remote search, compare/sync, remote editor and batch operations still require their own verified source-level implementation and exact 480×960 runtime screenshot comparison. UI cannot display fabricated server listings or progress. Real interactions for every enabled button and a physical-device audit remain mandatory. No unsupported features are claimed to have been completed.

Before merging or publishing: exact-head quality, protocol E2E, native Windows/Linux, macOS, Android emulator+instrumentation, Windows hardening and real screenshot QA must pass. A successful build alone does not establish 1:1 visual parity.

## Publication gating fix (16 October 2026)

The initial merged `0.95.22` source passed all six required PR CI workflows but failed its separate canonical release job because `version.json` still declared `channel: development` instead of the required `preview` or `stable`. This candidate declares `preview` and validates permitted channels during routine source-version checks so future PRs cannot silently reach release with a blocked channel. Publication must still use the exact merged main SHA, real verified artifacts, an immutable tag, and the release workflow; v0.95.22 is not to be claimed as published until GitHub confirms its assets.
