# Ghost FTP 0.95.10 — unambiguous direct Connect and reusable profiles

**Unpublished development candidate.** Latest confirmed public release: [v0.95.9](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.95.9), immutable source `de31ea3783f4b61069eda4db4e11078c96075415`, 21 assets.

## Implemented

- Windows and Linux: Files' Quick Connect accepts host, username, masked transient password, port and protocol; Connect invokes `connectionsStore.connectTemporary(profile)` and never opens the saved-site editor. The duplicated New Connection button in the Files header is removed.
- New Connection from the sidebar saves reusable connection profiles **only after Save profile**. The editor no longer connects on Save or silently auto-saves. Connection testing does not save.
- macOS: Creating a New connection now uses an unsaved draft, eliminating empty persisted sites. Files offers a direct FTP Connect that does not create a stored profile. Only FTP has a live macOS session engine; do not imply FTPS/SFTP parity.
- Android: Existing Connect continues to connect immediately; a separate Save new connection profile action stores metadata only in private app preferences. Saved profiles can be loaded by name without credentials. A new session requires the password to be re-entered.
- Shared branding and accessible control labels preserved. No demo data or fake connections introduced.

### Platform limitations

- macOS FTPS and SFTP still require real transport implementation; this PR does not invent it.
- Saved Android profiles deliberately exclude passwords and other secrets. The user must authenticate again.
- Physical-device pixel-perfect parity and Issues #126–#128 remain separate open acceptance work.
