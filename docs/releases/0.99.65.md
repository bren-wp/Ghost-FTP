# Ghost FTP 0.99.65 Preview — source candidate

**Published? No.** Previous verified public release is [v0.99.64](https://github.com/bren-wp/Ghost-FTP/releases/tag/v0.99.64). Candidate source is PR [#293](https://github.com/bren-wp/Ghost-FTP/pull/293).

## Included in the candidate

- FTP/FTPS/SFTP live session health monitoring while the window runs; a dead FTP/FTPS control socket receives one bounded reconnect and fresh probe, rather than automatically clearing the tab.
- Explicit FTP/SSH Disconnect blocks later reconnect and keeps other sessions independent.
- FTP/FTPS/SFTP uploads stage in unique sibling `.ghostftp-upload-*.part` files; only verified completed transfers proceed to remote rename. Failed or partial staging does not truncate an existing final file.
- Explicit Overwrite policy persists across retry; older persisted upload retry descriptors are non-overwriting by default.
- Focused Rust regressions for session recovery, temporary path creation, unsafe names and staging path isolation.

## Release limitations and gates

Remote rename-overwrite differs across FTP/SFTP servers; if unsupported, promotion reports an error and does not force deletion of the existing final file. FTP has no atomic create-exclusive STOR or rename-if-absent. Failure can leave a remote temporary file. Cloud, WebDAV, Agent and SaaS upload paths are not part of this staging change. No end-to-end 4+ GiB parallel matrix or native Windows Credential Manager/Linux Secret Service reopen matrix is declared complete by this candidate.

See [security audit](../audits/SESSION_LIVENESS_REMOTE_UPLOAD_AUDIT_0.99.65.md) and [test plan](../qa/LARGE_TRANSFER_AND_VAULT_ACCEPTANCE_0.99.65.md). No release shall be described as accepted before exact-SHA CI and native user-environment checks pass.
