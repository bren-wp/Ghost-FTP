# Ghost FTP privacy

Ghost FTP **1.1.1 Stable** is designed to operate without application telemetry, advertising, behavioral analytics, fingerprinting, hidden crash upload or a mandatory Ghost FTP account.

## Data Ghost FTP does not intentionally collect

Ghost FTP does not include a product service that receives:

- usage analytics;
- advertising identifiers;
- filenames for analytics;
- saved server profiles for synchronization;
- connection history for marketing;
- passwords or private-key passphrases;
- machine inventory for a Ghost FTP account.

Production CI and release workflows explicitly execute `go telemetry off` and verify that Go telemetry remains disabled.

## Normal network activity

Network traffic is generated by user-directed FTP, FTPS or SFTP actions against the server the user selected. Keepalive, listing, diagnostics and transfer metadata are part of that server interaction, not a Ghost FTP telemetry channel.

Fresh quick-connect defaults use FTPS; plain FTP remains an explicit unencrypted compatibility choice. Ghost FTP does not silently downgrade a failed secure FTPS request to FTP.

Ghost FTP does not silently download protocol runtimes or networking SDKs while the application is running.

## Connection diagnostics

Connection failures are converted into privacy-safe categories and remediation text. The diagnostic layer is tested so user-facing errors do not intentionally reproduce passwords, passphrases or protected profile payloads.

When reporting a problem, users should still review logs and remove real hostnames/paths if those details are confidential.

## Saved profiles

Profiles are local. Saving a site does not create a cloud record.

Credential persistence is opt-in:

- Windows uses the current-user operating-system protection boundary;
- Linux uses local authenticated encryption with user-private key material.

Ghost FTP 1.1.1 applies the same explicit credential-save consent policy to the main profile-save path and Windows Site Manager. Declining consent can still save the non-secret profile fields, but newly entered password/passphrase values are not persisted and retained stored credentials are removed when the chosen flow requires clearing them.

A protected secret is not meant to become plaintext JSON merely because decryption failed. The safe fallback is to request the secret again.

## Session-only secrets

Quick/ad-hoc connection credentials can remain runtime-only. Passwords and key passphrases should not be written to disk unless the user chooses the product's saved-credential option and the platform protection path succeeds.

On Linux, process-local protected-secret handles distinguish session-owned and borrowed profile-owned secrets. Session-owned handles are forgotten promptly on close or failed/abandoned SFTP setup; borrowed profile secrets are not invalidated merely because a connection session ends.

## Settings

Language, appearance, transfer preferences, recent local state and other desktop settings are stored locally. Settings recovery uses local backup/replacement behavior and does not contact BRENDIGO LTD.

Classic Light is the fresh/fallback appearance. Selecting Dark is an explicit local preference and does not load remote themes, fonts or style services.

## Transfer data

Ghost FTP necessarily reads local files selected for upload and writes files selected for download. Transfer content is sent only to/from the selected server through the chosen protocol.

Staging, rollback and source-snapshot files are local operational state. They are not uploaded to a Ghost FTP product service.

## GitHub Release and Packages privacy

Official release artifacts are built in GitHub Actions from repository source. The release allow-list includes only product binaries/packages plus generated verification files.

The stable GitHub Package (`ghcr.io/bren-wp/ghost-ftp`) is built from the verified `release/` directory only. The OCI bundle does not intentionally contain saved profiles, user files, local application data, signing private keys or CI secrets. Docker networking is disabled during the bundle build.

## Signing secrets

Production Authenticode credentials are expected to exist only as protected GitHub Actions secrets. Temporary PFX material is written into the runner's temporary directory for signing and removed after use. Private signing material must never be committed to the repository or included in release/package files.

## Documentation and screenshots

Maintained UI screenshots are captured from the real Windows x64 Portable executable by the dedicated CI workflow. Screenshots and fixtures must contain only synthetic/non-sensitive values and must not expose real customer hosts, usernames, credentials or local private paths.

## Logs and support

Ghost FTP aims to make operational logs useful without exposing credentials. Users should not paste real passwords, private keys, passphrases or confidential server content into public support requests.

## Third-party servers and tools

A server chosen by the user can observe the protocol traffic necessary for that connection and is governed by the server operator's own policy. System FTP/SFTP tools invoked by Ghost FTP operate under the local operating system and their own implementation behavior.

## No sale of user data

Ghost FTP contains no advertising data broker integration and no product backend designed to sell application usage/profile data.
