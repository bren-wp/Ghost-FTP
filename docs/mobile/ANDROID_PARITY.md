# Ghost FTP Android parity

Ghost FTP Android must follow the same product identity as the Windows and Linux app while using a mobile-first native layout.

## Identity contract

- Product name: Ghost FTP
- Brand owner label: Brendigo
- Version: 2.1.1-rc.22
- Display version: 2.1.1 RC22
- Badge: RC22
- Build: 2026.09.24.22

## Interface contract

Android keeps the same primary product model as the desktop app:

- One application surface.
- Connection-first workflow.
- FTP, explicit FTPS and SFTP protocol choices.
- SFTP host key fingerprint field for server identity verification.
- Remote workspace with remote folder listing.
- Tap-to-open folders.
- Tap-to-select files.
- Transfer actions for download, upload, remote file delete and remote folder creation.
- Transfer status state in the same screen.
- Guarded confirmation for upload target writes and remote file deletion.
- Bounded event queue for long mobile sessions.
- Settings and privacy messaging inside the same app surface.
- Clear disconnect behavior.
- No account requirement.
- No telemetry requirement.

## Mobile layout rules

- Prioritize one-handed use.
- Keep Connect, Disconnect and Refresh visible in the connection card.
- Keep Download, Pick file, Upload, Delete file and Create folder in the transfer section.
- Avoid desktop-only window concepts in Android copy.
- Keep server, transfer and privacy state visible without modal clutter.
- Use confirmation dialogs only for actions that write to or remove remote content.
- Keep the transfer queue bounded so repeated actions do not push the UI into an unstable long-scroll state.
- Do not persist passwords in ordinary app storage.
- Do not show sample hosts, sample accounts or placeholder copy in the app UI.

## Protocol contract

- FTP must open a session and list the selected remote path.
- FTP must download, upload, delete a remote file and create a remote folder.
- Explicit FTPS must open a protected session and list the selected remote path.
- Explicit FTPS must download, upload, delete a remote file and create a remote folder over protected data channels.
- SFTP must open an SSH file-transfer session, verify the SHA-256 host key fingerprint and list the selected remote path.
- SFTP must download, upload, delete a remote file and create a remote folder without disabling strict host-key checking.
- Passwords must stay in memory for the active action and be cleared on disconnect.
- Android downloads must go into app-private Android download storage.
- Android uploads must use the Android document picker and show the selected local file before upload.
- Remote targets containing `.` or `..` path segments must be rejected before transfer execution.
- Upload, delete and folder creation must refresh the remote workspace after success.

## Release contract

Every RC22 GitHub release must include Windows, Linux and Android APK assets plus SHA-256 checksums. The Android APK must come from the verified Android workflow artifact for the same release source commit.

The Android release path must not require GitHub signing secrets. The release path is designed to produce an installable APK without manual key setup.

An Android APK or AAB must not be treated as final unless all of the following are true:

- Android native build passes.
- Android UI review confirms the mobile layout matches the Ghost FTP product identity.
- FTP, explicit FTPS and SFTP protocol acceptance passes on Android.
- Download, upload, remote file delete and remote folder creation pass on Android.
- SFTP host-key fingerprint verification is active.
- Guarded remote write/delete confirmation and bounded transfer queue are present.
- Android release artifacts and checksums are generated by a dedicated release workflow.
- Documentation clearly separates Android artifacts from Windows and Linux artifacts.
