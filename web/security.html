Security

Fail closed where identity matters.

Ghost FTP treats protocol identity, release signatures and filesystem boundaries as explicit security contracts instead of optional polish.

FTP and FTPS

Plain FTP is intentionally unencrypted and should only be used when that risk is understood. Explicit FTPS requires TLS certificate and hostname validation and must not silently downgrade to FTP.

SFTP

Maintained desktop SFTP uses strict host-key trust/pinning. Web FTP requires the user to provide the expected SHA-256 server host-key fingerprint before authentication. Unknown or mismatching fingerprints are rejected.

Web destination protection

The supplied Web FTP deployment blocks loopback, link-local, private and reserved destination addresses by default. DNS results are validated before use and FTP/FTPS cURL requests pin the validated address while preserving the original hostname for TLS verification.

Production release identity

Windows publication requires a trusted Authenticode identity. Android publication requires the protected production keystore and an exact configured certificate SHA-256 match. CI-only or self-signed identities are never accepted as production substitutes.

Reporting

Do not publish credentials or private server details in a public report. Use the support path documented in the repository when reporting a vulnerability.
